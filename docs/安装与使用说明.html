AdGuard Home 管理中心 使用说明

本插件负责安装、DNS 接管、过滤、看护与统计；更细的高级项仍可在 AdGuard Home 面板中设置。

适用版本 1.3.13-5 OpenWrt / ImmortalWrt / iStoreOS

1. 快速开始

步骤 做什么 位置
1 安装插件 LuCI 上传 ipk，或 25.12 系统运行 install.sh
2 安装内核 服务 → AdGuard Home 管理中心 → 概览
3 一键启用 概览 → 一键启用
4 打开 AGH 面板 概览 → 打开 AGH 面板

默认配置：

  • 面板：0.0.0.0:13800（局域网可访问；仅本机访问改为 127.0.0.1）
  • 账号：admin / admin123（默认弱口令，首次登录后必须修改）
  • DNS：接管 53 端口，DNSMasq 移到 1745
  • 上游：127.0.0.1:1745
  • 过滤规则：预置订阅按设备内存自动选档（512MB 3 个 / 1GB 4 个 / 2GB+ 6 个分类列表，档内已去重）；白名单默认添加但不启用
  • 日志/统计：保留 30 天，查询日志只存内存
  • DNS 缓存：默认开启，16MB，最小 TTL 0（不覆盖），乐观缓存关闭
  • 加密上游：默认关闭；仅「Clash 前置」模式可开启（阿里 / DNSPod / Cloudflare DoH 或自定义）
  • DNSSEC、fallback：默认关闭

首次登录后请在「基础设置 → 插件配置」更换密码。

2. 安装

2.1 选择安装方式

系统 使用
OpenWrt 23.05 / 24.10、ImmortalWrt、iStoreOS 24.10 luci-app-adguardhome-lite_&lt;版本&gt;_all.ipk
OpenWrt 22.03 及更早（原生 Lua LuCI） luci-app-adguardhome-lite_&lt;版本&gt;-legacy_all.ipk
OpenWrt / iStoreOS 25.12 及 apk 系统 install.sh
离线安装 luci-app-adguardhome-lite_&lt;版本&gt;.run

同一设备只装一个。安装前先卸载旧版 luci-app-adguardhome 和 luci-i18n-adguardhome-zh-cn，并确认旧服务已停止。

升级或重装会保留 /etc/config/adguardhome_lite，默认 13800 只对新安装生效；旧设备可在「基础设置 → 插件配置」中修改端口。

2.2 ipk / run

LuCI 上传：

  1. 打开 系统 → 软件包 → 上传安装包；
  2. 选择对应 .ipk，等待依赖安装完成；
  3. 在 服务 菜单打开 AdGuard Home 管理中心。

命令行安装：

opkg install /tmp/luci-app-adguardhome-lite_<版本>_all.ipk

离线包：

sh /tmp/luci-app-adguardhome-lite_<版本>.run

.run 会优先安装新版 LuCI 包，失败时回退 legacy 包。

2.3 脚本安装（25.12 / apk 系统）

OpenWrt / iStoreOS 25.12 起改用 apk，不能安装 .ipk，请使用 install.sh（OpenWrt 23.05 / 24.10、ImmortalWrt、iStoreOS 也可使用）：

curl -fsSL https://raw.githubusercontent.com/Ozero-top/luci-app-adguardhome-lite/main/install.sh | sh

只有 wget 时：

wget -qO- https://raw.githubusercontent.com/Ozero-top/luci-app-adguardhome-lite/main/install.sh | sh

国内网络可走反代：

curl -fsSL https://gh-proxy.org/https://raw.githubusercontent.com/Ozero-top/luci-app-adguardhome-lite/main/install.sh | sh -s -- -m https://gh-proxy.org

常用参数：

参数 作用
-v &lt;版本&gt; 指定版本；latest 取最新 Release
-f / --force 强制更新，用 main 分支最新代码覆盖
-m &lt;地址&gt; 指定 GitHub 反代，可重复
--no-deps 跳过依赖安装
--keep-old 只检测旧版残留，不自动清理
--purge-old 清理旧版时一并删除旧统计数据（保留 /etc/AdGuardHome.yaml）
--src DIR 从本地源码目录安装（开发调试用）
--uninstall 卸载并恢复 DNS，保留配置与内核
--purge 卸载并删除配置、内核与统计 
# 强制更新（不升版）
    sh install.sh -f

    # 卸载（保留配置）
    sh install.sh --uninstall

脚本安装不会写入 apk 已安装列表，后续升级和卸载继续用 install.sh。 iStoreOS 25.12 首次使用如提示“未设置密码”，先在 LuCI 设置管理员密码，或 SSH 执行 passwd root。

2.4 安装后检查

  • 「服务」菜单出现 AdGuard Home 管理中心；
  • 概览能显示运行状态；
  • 安装内核后显示实际内核版本（带 -b 的预发布版本会完整显示）；
  • 一键启用后显示「运行中」；
  • 局域网执行 nslookup www.baidu.com 路由器IP 能正常解析。

可选 SSH 检查：

uci show adguardhome_lite
    /etc/init.d/adguardhome_lite status
    uci get dhcp.@dnsmasq[0].port          # 接管 53 时应为 1745
    nft list chain inet fw4 agh_dns_redirect

接管 53 时：AdGuard Home 监听 53，DNSMasq 监听 1745。不要把 DNSMasq 的 server 写成单值 option server '...'，需要修改时用 uci add_list，或直接在插件里重新保存接管方式。

2.5 旧版残留检测与清理

概览页会自动扫描旧版残留，检测到时会显示「检测到旧版残留」卡片，可一键清理：

  • 旧插件包：luci-app-adguardhome、luci-i18n-adguardhome-zh-cn
  • 旧服务与旧 LuCI 控制器 / 视图文件
  • 旧内核：/usr/bin/AdGuardHome、/usr/sbin/AdGuardHome
  • 旧配置模板：/etc/config/adguardhome_lite-opkg、/etc/config/adguardhome-opkg（opkg 升级时把旧 conffile 另存的文件，没有任何代码引用，卸载也不会删除；只备份后删除，不动当前 /etc/config/adguardhome_lite）

清理会先停止并禁用旧服务，把文件和旧内核备份到 /etc/adguardhome_lite/legacy-backup-时间戳/，然后删除；/etc/AdGuardHome.yaml 与统计数据会保留。

脚本安装同样会在安装前自动检测并清理，可用 --keep-old 只检测不清理，--purge-old 一并删除旧统计数据。

3. 三步启用

第 1 步：安装内核

  1. 打开 概览；
  2. 点击 安装/更新内核；
  3. 等待进度完成。

插件会自动识别 CPU 架构，从 AdGuard 官方源下载对应内核。国内网络可在 基础设置 → 插件配置 选择 GitHub 反代（推荐 gh-proxy.org）；fake-IP 环境会自动解析真实 IP 后下载。

安装过程中「安装进度」会显示下载百分比或已下载大小、完成后记录用时；概览的「内核版本」行在有新版本时会显示「可更新」，第 1 步的说明也会同步提示，点击提示可跳到安装按钮。正式版、预发布版、旧版本三条通道各自判断，互不覆盖。

选择「预发布版」时，页面提示过具体版本会直接按该版本下载，未取到时先从 GitHub Releases 取最新的预发布标签（可走反代），失败后依次回退官方预发布通道与正式版；概览页内核版本旁会标注「预发布版」。

选择「旧版本」时按上一条正式版本线（如 v1.0.0 之前为 v0.107.x）的最高版本安装。旧版本内核读不了已升级的配置 schema 时，会自动从 /etc/AdGuardHome.yaml.bak-* 里选一份能通过校验的备份并恢复；没有兼容备份则取消安装、内核保持原样。每次更换内核前都会备份配置，便于回退。

第 2 步：一键启用

首次启用会从内置模板生成 /etc/AdGuardHome.yaml，并写入默认账号、中文界面、过滤规则、日志周期和 DNS 接管配置。

默认采用「接管 53 端口」：AdGuard Home 监听 53，DNSMasq 移到 1745，上游指向 127.0.0.1:1745。

第 3 步：打开 AGH 面板

点击 打开 AGH 面板，用概览页显示的账号密码登录。过滤规则、上游 DNS、安全搜索、家长控制、查询日志都在 AdGuard Home 面板中操作。

4. 常用设置

DNS 接管方式 推荐「接管 53 端口」；装了 PassWall / PassWall2 用「PassWall 前置」，详见第 5 节
管理面板端口 默认 13800，不能占用 53 / 1745 / 5333 / 5335
面板监听地址 0.0.0.0 局域网可访问（默认）；127.0.0.1 仅本机可访问，适合只通过 LuCI 内嵌面板使用
内核安装位置 内置存储重启保留；内存临时重启后需重装

成人内容拦截 开启后追加 HaGeZi NSFW 规则，关闭即移除
DNS 缓存 默认开启；可选 8/16/32/64/128MB，默认 16MB
上游 DNS 默认自动；可改为自定义列表，支持 [/域名/]IP 条件转发
最小 / 最大 TTL 默认 0 / 0 秒；最小 0 表示不覆盖上游 TTL，最大 0 表示不限制

过滤规则 启用/停用订阅、添加订阅（黑名单/白名单）、自定义规则，立即生效

下载源 档位右侧选择 jsDelivr（默认）/ GitHub 直连 / 自建备用；切换后已有预置列表原地改到新源并立即重新下载，结果记入运行日志
日志与统计保留 可选 7/30/90/180/365 天，保存后重启服务

缓存是内存缓存，重启 AdGuard Home 后清空。关闭缓存只停止缓存，不清空其他配置。 插件只更新自己写入的 http_proxy、本地 PTR 和上游 DNS；在 AdGuard Home 面板或 YAML 里手动改过的对应项会保持不变。DNSSEC、上游模式也只在首次生成配置时给默认值，之后以 AGH 面板为准。 加密上游只保护「AdGuard Home → 真实上游」这一段。「接管 53」「DNSMasq 上游」等模式的上游是本机 DNS，开启加密不会生效；默认由 Clash/代理负责出公网的加密。 「接管 53」模式下自定义上游会绕过本机 DNSMasq(1745)，xxx.lan 等本地主机名将无法解析；需要保留本地解析时，请在自定义列表末尾加上 127.0.0.1:1745。 AdGuard Home 的 ratelimit 按 /24 网段限速，默认 20 qps；本插件新装模板放宽到 100。升级用户若设备较多、出现偶发 DNS 超时，可在 AGH 面板把 ratelimit 调大或设为 0。

高级配置：直接编辑 /etc/AdGuardHome.yaml，保存前自动执行 --check-config，失败不覆盖，并保留 .bak 备份。

DNS 自检：概览页点「开始检测」，只读检查内核文件、进程、管理端口和本机 53 查询链路，不会修改配置；失败项会给出具体原因，适合保存设置或切换接管方式后快速确认。

运行日志：查看最近 300 行系统日志、内核安装日志和最近一次服务操作日志，支持下载；级别可选「全部 / 仅错误 / 仅警告」，每条记录带原因码（如 dns_hijack_conflict、core_integrity_failed）。「查询日志」子页可按「全部 / 已拦截 / 已放行」筛选、搜索域名或设备、翻页查看，每条记录显示命中的规则与所属订阅；默认每 5 秒自动刷新，可在下拉框调整间隔或关闭。

5. DNS 接管方式

方式 AdGuard Home DNSMasq 适合
接管 53 端口（默认） 53 1745 想逐设备统计，装了 Clash 也能用
PassWall / PassWall2 前置 53 1745 用 PassWall 或 PassWall2 做分流，不想关它的 DNS 劫持
DNSMasq 上游 5333 53 不想让 AdGuard Home 占 53，且没有程序抢 53
Clash 前置 5335 53 不想占 53，不需要逐设备统计
仅面板 不接管 53 只想打开面板查看

怎么选：需要逐设备统计、所有域名先过滤，选「接管 53 端口」；装了 PassWall / PassWall2、又不想关闭它的 DNS 劫持，选「PassWall 前置」；不想让 AdGuard Home 占 53，选「Clash 前置」；只想看面板，选「仅面板」。

旧「Clash 串联」已下线，旧配置会自动迁移为「接管 53 端口」。前置模式会自动把 Clash 自定义上游指向 127.0.0.1:5335，停止或切换时恢复原值。

与 Clash 共存：选「接管 53」时，插件会创建 agh_dns_redirect 链，把局域网设备的 53 查询收回路由器，Clash 劫持指向 :53、:1745 或 :7874 都不会绕过过滤。

与 PassWall / PassWall2 共存：选「PassWall 前置」时不需要关闭它们的 DNS 劫持。收回链改用 priority -102（PassWall 为 -101），先于它接住设备的 53 查询；AdGuard Home 上游自动指向 PassWall 自己的 DNS（地址用路由器局域网 IP，端口从运行时变量读取：PassWall 1.x 读 /tmp/etc/passwall/var 的 ACL_default_dns_port，默认从 11400 起分配；PassWall2 读 /tmp/etc/passwall2/var 的 ACL_acl_default_dns_port，默认从 2001 起分配；两者都启用时以 PassWall2 为准）。之所以不用 127.0.0.1：PassWall 自带的 dnsmasq 开了 local-service，只回答局域网来源的查询，用回环地址会被拒绝，表现为只有缓存能解析、新域名全部失败。PassWall 未启用时上游回退为 127.0.0.1:1745，不会断网。该模式不支持「排除接口 / 客户端」，排除的设备会直接走 PassWall。

检查：

nft list chain inet fw4 agh_dns_redirect

看到 redirect to :53 即为正常；没有这条链时，重新保存一次「接管 53 端口」。

切换与停止：切换方式会先恢复接管前的 DNSMasq 原值，再按新方式配置；停止或卸载时恢复端口、noresolv、resolvfile 和 server，不会写入公共 DNS。

启动顺序：DNSMasq（19）→ AdGuard Home（95）→ Clash / PassWall（99），插件已注册 START=95，无需手动调整。「PassWall 前置」下 PassWall 启动后才会开始分流，上游按默认端口（1.x 11400 / 2.x 2001）预写，不阻塞上网。

端口跟随：PassWall / PassWall2 的 DNS 端口是动态分配的（1.x 从 11400 起、2.x 从 2001 起找空闲端口），看护进程每 10 秒检查一次；端口变化且上游仍由插件管理时，新端口需连续稳定 25 秒才判定有效，随后自动改写上游并重启 AdGuard Home（SIGHUP 不会应用上游变更），不重启 PassWall；端口在 PassWall 重启期短暂消失不会触发反复重启；自定义上游不会被改动。

排除接口 / 客户端：仅「接管 53」生效。命中的查询直接交给 DNSMasq（1745），不进入 AdGuard Home，也不计入统计；指向外部 DNS 的查询直接放行。

自定义域名转发：DNSMasq 里的 server=/corp.example/10.0.0.1 会保留。「接管 53」下查询仍先经过 AdGuard Home，过滤和统计正常；「DNSMasq 上游」下这类域名直接发给指定服务器，不经过 AdGuard Home。需要过滤时，改用 AdGuard Home 上游的 [/corp.example/]10.0.0.1 写法。

命令行查看状态：

sh /usr/share/adguardhome-lite/dns_mode.sh status        # 人读文本，一行一项
    sh /usr/share/adguardhome-lite/dns_mode.sh status-json   # 单行 JSON，供监控/脚本消费

status-json 字段：dns_mode、mode_applied、agh_dns_port、dnsmasq_port、dnsmasq_noresolv、lan_dhcp_option、added_dhcp_option、dnsmasq_dns_redirect、added_dns_redirect、openclash_hijack_port、agh_bypassed、passwall_enabled、passwall_dns_port、passwall_dns_redirect。可与 jsonfilter 组合：

sh /usr/share/adguardhome-lite/dns_mode.sh status-json | jsonfilter -e '@.mode_applied'

6. 常见问题

Q1：内核下载失败？

检查网络和系统时间；国内网络启用 GitHub 反代；fake-IP 环境已自动处理；空间不足时把内核位置改到内置存储。

预发布版会依次尝试 GitHub 预发布（含反代）→ 官方预发布通道 → 正式版，全部失败才会报错；安装日志里能看到每个下载地址的尝试结果与下载进度。

Q2：启用后不能上网？

概览页点「停止并关闭自启」，插件会恢复 DNSMasq。仍异常可执行：

/etc/init.d/adguardhome_lite stop
    /etc/init.d/dnsmasq restart

Q3：停止服务后面板打不开？

正常现象，面板随服务停止。重新点「启动服务」即可。

Q4：改了面板端口打不开？

等待 5–10 秒，确认服务运行中，并检查 UCI 与 YAML 是否一致：

uci get adguardhome_lite.main.webport
    grep -m1 '^  address:' /etc/AdGuardHome.yaml

Q5：同时运行 Clash 时去广告不生效？

先确认 agh_dns_redirect 链存在：

nft list chain inet fw4 agh_dns_redirect

没有 redirect to :53 时，重新保存一次「接管 53 端口」。

Q6：设备能连路由器但打不开网页？

多为设备没拿到 IPv4 DNS。「接管 53」「PassWall 前置」启用时会自动给 LAN 追加一条 6,路由器IP（停止、切换或卸载时只移除插件自己加的那条）；仍异常时可手动补：

uci add_list dhcp.lan.dhcp_option='6,路由器IP'
    uci commit dhcp
    /etc/init.d/dnsmasq restart

设备断开重连后生效。

Q7：重启后内核消失？

内核装在 /tmp 内存位置时会这样。重新安装内核，或把安装位置改到内置存储。

Q8：忘记面板密码？

进入「基础设置 → 插件配置」，输入新密码保存即可，不需要旧密码。

Q9：升级 OpenWrt 固件后？

/etc/AdGuardHome.yaml 和过滤缓存会保留；内核文件较大，不进入固件备份，升级后需要重新安装内核。

Q10：开启「安全浏览」后解析变慢？

安全浏览依赖 family.adguard-dns.com，国内不可达时会拖慢解析。到 AdGuard Home 面板关闭「安全浏览」，或执行：

sed -i 's/^  safebrowsing_enabled: true/  safebrowsing_enabled: false/' /etc/AdGuardHome.yaml
    /etc/init.d/adguardhome_lite restart

Q11：过滤规则一直更新失败？

通常是直连 raw.githubusercontent.com 失败。插件会自动检测 Clash 的 HTTP 代理并写入 http_proxy：

grep -n '^http_proxy' /etc/AdGuardHome.yaml

为空时启动 Clash，再回插件重新保存一次设置。

需要立刻生效或某个源不可用时，在「过滤规则」页档位右侧切换「下载源」：插件会把已有预置列表的地址原地改到新源，并由 AdGuard Home 立即重新下载；列表数量不变，不会新增副本或备份文件，自定义订阅与白名单不受影响。某个源下载失败时会按 jsDelivr → GitHub 直连 → 自建备用 → 配置的反代的顺序重试。每次切换会写入「运行日志 → 订阅更新日志」，保留最近 100 次。

Q12：出问题怎么快速定位？

先到概览点「开始检测」，DNS 自检会逐项检查内核、进程、13800 面板端口与本机 53 查询链路，全程只读；再到「运行日志」把级别切到「仅错误」，每条记录都带原因码，能直接看出是下载、校验、写入还是接管环节失败。反馈问题时附上错误行与原因码即可。

  • /etc/AdGuardHome.yaml

opkg remove luci-app-adguardhome-lite
    rm -f /usr/bin/AdGuardHome/AdGuardHome
    rm -rf /etc/AdGuardHome
    rm -f /etc/AdGuardHome.yaml

10. 安全建议

  • 不要将 13800 面板端口映射到公网。
  • 面板监听地址默认 0.0.0.0（同网段可访问）。不需要局域网直连时改为 127.0.0.1，只保留 LuCI 内嵌面板入口。
  • 默认密码 admin123 仅供首次登录，请立即在「修改密码」中重设。
  • 面板密码以明文保存在 /etc/config/adguardhome_lite（AGH 哈希不可逆，插件调用本机 API 需要原文），该文件权限已收紧为 600，请勿自行放宽。
  • 「接管 53」会调整 DNSMasq，若同时运行 Pi-hole、旧版 AdGuard Home 或自建 DNS，请先确认端口不冲突。
  • 高级配置会直接修改 /etc/AdGuardHome.yaml，修改前请备份。
  • 对安全要求高的环境，请为 LuCI 启用 HTTPS。
