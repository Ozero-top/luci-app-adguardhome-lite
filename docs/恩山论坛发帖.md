# 【原创】AdGuard Home 助手 —— OpenWrt / iStoreOS 三步安装、自动接管 DNS 的轻量 LuCI 插件

## 一、先说结论

这是一个轻量的 LuCI 管理插件，只做三件事：**装内核、接 DNS、看状态**。

- 不用自己找 AdGuard Home 内核，插件自动识别架构下载；
- 不用手改 DNSMasq，默认接管 53 端口，停止或卸载自动还原；
- 常用过滤、缓存、上游都能在插件页面里改，不用来回切面板。

项目开源，代码与安装包都放在 GitHub，插件本身不修改固件，也不影响系统其它功能。

## 二、适用环境

| 项目 | 说明 |
|---|---|
| 固件 | OpenWrt 23.05 / 24.10、ImmortalWrt、iStoreOS，以及基于新版 LuCI 的衍生固件 |
| 旧固件 | OpenWrt 22.03 及更早的原生 Lua LuCI，使用 legacy 安装包 |
| 25.12 / apk 系统 | 不能装 `.ipk`，用 `install.sh` 脚本安装 |
| 架构 | x86_64 / 386、ARM64、ARM v5~v8、MIPS / MIPSel / MIPS64、RISC-V 64、PPC64LE |
| 暂不支持 | LoongArch；Docker、NAS、普通 Linux 发行版 |

实测环境：Kwrt aarch64、iStoreOS 24.10 / 25.12 x86_64，内核 AdGuard Home v0.107.80。

> 注意：与旧版 `luci-app-adguardhome` 冲突，安装前请先卸载旧插件及 `luci-i18n-adguardhome-zh-cn`。

## 三、功能特性

### 安装与内核

- 自动识别 CPU 架构，从官方源下载最新稳定版内核；
- 内置 GitHub 反代选项（`gh-proxy.org`、`ghproxy.cc`、`ghproxy.com`、`ghfast.top`），失败自动回退直连；
- 路由器使用 fake-IP DNS 时，自动解析真实 IP 后再下载。

### DNS 接管

- 四种方式：接管 53 端口（默认）、DNSMasq 上游、Clash 前置、仅面板；
- 与 Clash 共存：自建 `agh_dns_redirect` 链，在 Clash 劫持之前收回设备的 53 查询，过滤和逐设备统计都能保留；
- 支持按接口、按客户端 IP / CIDR 排除，不参与过滤的设备直接交给系统 DNSMasq；
- 上游可自定义，支持 `tls://`、`https://`、`quic://` 和 `[/域名/]IP` 条件转发；
- 停止服务或卸载时，只还原插件自己改过的 DNSMasq 设置，不写入公共 DNS。

### 过滤与统计

- 概览直接显示 DNS 查询、已拦截、恶意/钓鱼、成人内容四项统计；
- 过滤规则页可启用/停用订阅、添加黑名单或白名单订阅、编辑自定义规则，保存立即生效；
- 安全搜索、浏览安全、成人内容拦截（HaGeZi NSFW）一个开关即可；
- 运行日志里可看最近 20 条查询与拦截结果；
- 统计与查询日志保留天数可调。

### 维护

- 页面内可重置面板密码，不需要旧密码；
- 高级配置可直接编辑 `/etc/AdGuardHome.yaml`，保存前自动执行 `--check-config`，失败不覆盖并保留 `.bak`；
- 插件版本提示，每 24 小时检查一次更新。

## 四、安装

### 方式一：安装包（推荐）

到 GitHub Releases 下载，同一台设备只装一个：

| 安装包 | 适用固件 |
|---|---|
| `luci-app-adguardhome-lite_<版本>_all.ipk` | 新版 LuCI 固件 |
| `luci-app-adguardhome-lite_<版本>-legacy_all.ipk` | 旧版 LuCI 固件 |
| `luci-app-adguardhome-lite_<版本>.run` | 离线自解压包，内含上面两个 ipk |

LuCI 上传：系统 → 软件包 → 上传安装包 → 选择 `.ipk` → 等待依赖装完，在「服务」菜单打开 **AdGuard Home 助手**。

[图片：LuCI 软件包上传页面截图]

命令行：

```sh
opkg install /tmp/luci-app-adguardhome-lite_<版本>_all.ipk
```

### 方式二：脚本安装（25.12 / apk 系统）

```sh
curl -fsSL https://raw.githubusercontent.com/Ozero-top/luci-app-adguardhome-lite/main/install.sh | sh
```

只有 `wget` 时：

```sh
wget -qO- https://raw.githubusercontent.com/Ozero-top/luci-app-adguardhome-lite/main/install.sh | sh
```

国内网络可以走反代：

```sh
curl -fsSL https://gh-proxy.org/https://raw.githubusercontent.com/Ozero-top/luci-app-adguardhome-lite/main/install.sh | sh -s -- -m https://gh-proxy.org
```

常用参数：`-v` 指定版本、`-f` 强制更新、`--uninstall` 卸载保留配置、`--purge` 卸载并删除配置与内核。

## 五、三步上手

### 第 1 步：安装内核

概览 →「初始化配置」→ 点「安装/更新内核」，等待进度完成。

[图片：概览页初始化配置卡片，展示安装内核按钮]

### 第 2 步：一键启用

点「一键启用」。插件会从内置模板生成 `/etc/AdGuardHome.yaml`，默认接管 53 端口，DNSMasq 自动移到 1745。

默认配置：

| 项目 | 默认值 |
|---|---|
| 面板 | `0.0.0.0:13800` |
| 账号 / 密码 | `admin` / `admin123` |
| 上游 DNS | `127.0.0.1:1745` |
| 过滤规则 | 11 个订阅 + 1 个白名单 |
| 统计 / 查询日志 | 保留 30 天 |
| DNS 缓存 | 开启，16MB |

### 第 3 步：打开控制台

点「打开控制台」，用默认账号登录，首次登录后建议到「基础设置 → 插件配置」修改密码。

[图片：概览页运行状态与过滤统计]

## 六、DNS 接管方式怎么选

| 方式 | 链路 | 适合 |
|---|---|---|
| 接管 53 端口（默认） | 客户端 → 53 AdGuard Home → 1745 DNSMasq → 7874 Clash DNS / 上游 | 想逐设备统计；装了 Clash 也能用 |
| DNSMasq 上游 | 客户端 → 53 DNSMasq → 5333 AdGuard Home | 不想让 AdGuard Home 占 53，且没有程序抢 53 |
| Clash 前置 | 客户端 → Clash 劫持 → 7874 → 5335 AdGuard Home | 不想让 AdGuard Home 占 53，不需要逐设备统计 |
| 仅面板 | 不接管 DNS | 只想先看看面板 |

简单判断：**想看到每台设备、让所有域名先过滤，就选「接管 53 端口」**；装了 Clash 也推荐这个，插件会把设备的 53 查询先收回来，不会被劫持绕过。

[图片：基础设置 → 插件配置 页面，展示 DNS 接管方式与端口]

检查是否生效：

```sh
nft list chain inet fw4 agh_dns_redirect
```

看到 `redirect to :53` 即为正常。

## 八、常见问题

**Q：需要先手动安装 AdGuard Home 吗？**
不需要，插件自带内核安装流程；已有 `/etc/AdGuardHome.yaml` 会直接复用。

**Q：启用后不能上网？**
到概览点「停止并关闭自启」，插件会自动恢复 DNSMasq 原始设置；仍异常可执行：

```sh
/etc/init.d/adguardhome_lite stop
/etc/init.d/dnsmasq restart
```

**Q：同时运行 Clash 时过滤不生效？**
先执行 `nft list chain inet fw4 agh_dns_redirect`，没有 `redirect to :53` 时重新保存一次「接管 53 端口」。

**Q：停止服务后面板打不开？**
正常现象，面板随服务停止。重新点「启动服务」即可。

**Q：设备能连路由器但打不开网页？**
多为设备没拿到 IPv4 DNS，可补一条 DHCP 下发：

```sh
uci add_list dhcp.lan.dhcp_option='6,路由器IP'
uci commit dhcp
/etc/init.d/dnsmasq restart
```

**Q：重启后内核消失？**
内核装在 `/tmp` 时属于内存文件，重启即丢。把安装位置改为内置存储，或重新安装内核。

**Q：页面里的广告还在？**
路由器端只能按域名拦截，页面内广告位、同域推广和追踪脚本需要浏览器端过滤，建议搭配 AdGuard 扩展或 uBlock Origin。

**Q：卸载后 DNS 会恢复吗？**
会。停止或卸载时只写回接管前记录的端口、`noresolv`、`resolvfile` 和 `server`，不会写入公共 DNS。
