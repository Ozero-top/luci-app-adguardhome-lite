# AdGuard Home 助手 使用说明

适用版本：`1.2.0-1` ｜ 适用固件：OpenWrt / ImmortalWrt / iStoreOS

本插件只做三件事：**装内核、接 DNS、看状态**。过滤规则、查询日志、家长控制仍在 AdGuard Home 面板中设置。

---

## 1. 快速开始

| 步骤 | 做什么 | 位置 |
|---|---|---|
| 1 | 安装插件 | LuCI 上传 ipk，或 25.12 系统运行 `install.sh` |
| 2 | 安装内核 | 服务 → AdGuard Home 助手 → 概览 |
| 3 | 一键启用 | 概览 → 一键启用 |
| 4 | 打开控制台 | 概览 → 打开控制台 |

默认配置：

- 面板：`0.0.0.0:13800`
- 账号：`admin` / `admin123`
- DNS：接管 53 端口，DNSMasq 移到 1745
- 上游：`127.0.0.1:1745`
- 过滤规则：11 个 + 1 个白名单
- 日志/统计：保留 30 天，查询日志只存内存
- 缓存、DNSSEC、fallback：默认关闭

> 首次登录后请在「基础设置 → 修改面板密码」更换密码。

## 2. 安装

### 2.1 选择安装方式

| 系统 | 使用 |
|---|---|
| OpenWrt 23.05 / 24.10、ImmortalWrt、iStoreOS 24.10 | `luci-app-adguardhome-lite_<版本>_all.ipk` |
| OpenWrt 22.03 及更早（原生 Lua LuCI） | `luci-app-adguardhome-lite_<版本>-legacy_all.ipk` |
| OpenWrt / iStoreOS 25.12 及 apk 系统 | `install.sh` |
| 离线安装 | `luci-app-adguardhome-lite_<版本>.run` |

同一设备只装一个。安装前先卸载旧版 `luci-app-adguardhome` 和 `luci-i18n-adguardhome-zh-cn`，并确认旧服务已停止。

> 升级或重装会保留 `/etc/config/adguardhome_lite`，默认 `13800` 只对新安装生效；旧设备可在「基础设置」中修改端口。

### 2.2 ipk / run

LuCI 上传：

1. 打开 **系统 → 软件包 → 上传安装包**；
2. 选择对应 `.ipk`，等待依赖安装完成；
3. 在 **服务** 菜单打开 **AdGuard Home 助手**。

命令行安装：

```sh
opkg install /tmp/luci-app-adguardhome-lite_<版本>_all.ipk
```

离线包：

```sh
sh /tmp/luci-app-adguardhome-lite_<版本>.run
```

`.run` 会优先安装新版 LuCI 包，失败时回退 legacy 包。

### 2.3 脚本安装（25.12 / apk 系统）

25.12 起使用 `apk`，不能安装 `.ipk`。直接运行：

```sh
curl -fsSL https://raw.githubusercontent.com/Ozero-top/luci-app-adguardhome-lite/main/install.sh | sh
```

只有 `wget` 时：

```sh
wget -qO- https://raw.githubusercontent.com/Ozero-top/luci-app-adguardhome-lite/main/install.sh | sh
```

国内网络可走反代：

```sh
curl -fsSL https://gh-proxy.org/https://raw.githubusercontent.com/Ozero-top/luci-app-adguardhome-lite/main/install.sh | sh -s -- -m https://gh-proxy.org
```

常用参数：

| 参数 | 作用 |
|---|---|
| `-v <版本>` | 指定版本；`latest` 取最新 Release |
| `-f` / `--force` | 强制更新，用 main 分支最新代码覆盖 |
| `-m <地址>` | 指定 GitHub 反代，可重复 |
| `--no-deps` | 跳过依赖安装 |
| `--uninstall` | 卸载并恢复 DNS，保留配置与内核 |
| `--purge` | 卸载并删除配置、内核与统计 |

```sh
# 强制更新（不升版）
sh install.sh -f

# 卸载（保留配置）
sh install.sh --uninstall
```

> 脚本安装不会写入 `apk` 已安装列表，后续升级和卸载继续用 `install.sh`。
>
> iStoreOS 25.12 首次使用如提示“未设置密码”，先在 LuCI 设置管理员密码，或 SSH 执行 `passwd root`。

### 2.4 安装后检查

- 「服务」菜单出现 **AdGuard Home 助手**；
- 概览能显示运行状态；
- 安装内核后显示版本号；
- 一键启用后显示「运行中」；
- 局域网执行 `nslookup www.baidu.com 路由器IP` 能正常解析。

可选 SSH 检查：

```sh
uci show adguardhome_lite
/etc/init.d/adguardhome_lite status
uci get dhcp.@dnsmasq[0].port          # 接管 53 时应为 1745
nft list chain inet fw4 agh_dns_redirect
```

> 接管 53 时：AdGuard Home 监听 `53`，DNSMasq 监听 `1745`。不要把 DNSMasq 的 `server` 写成单值 `option server '...'`，需要修改时用 `uci add_list`，或直接在插件里重新保存接管方式。

## 3. 三步启用

### 第 1 步：安装内核

1. 打开 **概览**；
2. 点击 **安装/更新内核**；
3. 等待进度完成。

插件会自动识别 CPU 架构，从 AdGuard 官方源下载对应内核。国内网络可在 **基础设置** 选择 GitHub 反代（推荐 `gh-proxy.org`）；fake-IP 环境会自动解析真实 IP 后下载。

### 第 2 步：一键启用

首次启用会从内置模板生成 `/etc/AdGuardHome.yaml`，并写入默认账号、中文界面、过滤规则、日志周期和 DNS 接管配置。

默认采用「接管 53 端口」：AdGuard Home 监听 53，DNSMasq 移到 1745，上游指向 `127.0.0.1:1745`。

### 第 3 步：打开控制台

点击 **打开控制台**，用概览页显示的账号密码登录。过滤规则、上游 DNS、安全搜索、家长控制、查询日志都在 AdGuard Home 面板中操作。

## 4. 常用设置

| 设置项 | 说明 |
|---|---|
| 启用 AdGuard Home | 开启后启动服务；关闭后停止并恢复 DNSMasq 原始设置 |
| DNS 接管方式 | 推荐「接管 53 端口」，详见第 5 节 |
| 管理面板端口 | 默认 `13800`，不能占用 53 / 1745 / 5333 / 5335 |
| 内核安装位置 | 内置存储重启保留；内存临时重启后需重装 |
| 数据工作目录 | 保存统计和过滤缓存；内存临时会减少闪存写入 |
| 内核更新通道 | 稳定版 / 测试版 |
| GitHub 反代 | 仅加速内核下载，不修改系统网络 |
| 不参与接管的接口 | 仅「接管 53」可用，勾选后该接口的查询交给 DNSMasq |
| 不参与接管的客户端 | 仅「接管 53」可用，支持 IPv4 / IPv6 / CIDR |
| 成人内容拦截 | 开启后追加 HaGeZi NSFW 规则，关闭即移除 |

**高级配置**：直接编辑 `/etc/AdGuardHome.yaml`，保存前自动执行 `--check-config`，失败不覆盖，并保留 `.bak` 备份。

**运行日志**：查看最近 300 行系统日志、内核安装日志和最近一次服务操作日志，支持下载。

## 5. DNS 接管方式

| 方式 | AdGuard Home | DNSMasq | 适合 |
|---|---|---|---|
| 接管 53 端口（默认） | 53 | 1745 | 想逐设备统计，装了 OpenClash 也能用 |
| DNSMasq 上游 | 5333 | 53 | 不想让 AdGuard Home 占 53，且没有程序抢 53 |
| OpenClash 前置 | 5335 | 53 | 不想占 53，不需要逐设备统计 |
| 仅面板 | 不接管 | 53 | 只想打开面板查看 |

**怎么选**：需要逐设备统计、所有域名先过滤，选「接管 53 端口」；不想让 AdGuard Home 占 53，选「OpenClash 前置」；只想看面板，选「仅面板」。

> 旧「OpenClash 串联」已下线，旧配置会自动迁移为「接管 53 端口」。前置模式会自动把 Clash 自定义上游指向 `127.0.0.1:5335`，停止或切换时恢复原值。

**与 OpenClash 共存**：选「接管 53」时，插件会创建 `agh_dns_redirect` 链，把局域网设备的 53 查询收回路由器，OpenClash 劫持指向 `:53`、`:1745` 或 `:7874` 都不会绕过过滤。

检查：

```sh
nft list chain inet fw4 agh_dns_redirect
```

看到 `redirect to :53` 即为正常；没有这条链时，重新保存一次「接管 53 端口」。

**切换与停止**：切换方式会先恢复接管前的 DNSMasq 原值，再按新方式配置；停止或卸载时恢复端口、`noresolv`、`resolvfile` 和 `server`，不会写入公共 DNS。

**启动顺序**：DNSMasq（19）→ AdGuard Home（95）→ OpenClash（99），插件已注册 `START=95`，无需手动调整。

**排除接口 / 客户端**：仅「接管 53」生效。命中的查询直接交给 DNSMasq（1745），不进入 AdGuard Home，也不计入统计；指向外部 DNS 的查询直接放行。

## 6. 常见问题

### Q1：内核下载失败？

检查网络和系统时间；国内网络启用 GitHub 反代；fake-IP 环境已自动处理；空间不足时把内核位置改到内置存储。

### Q2：启用后不能上网？

概览页点「停止并关闭自启」，插件会恢复 DNSMasq。仍异常可执行：

```sh
/etc/init.d/adguardhome_lite stop
/etc/init.d/dnsmasq restart
```

### Q3：停止服务后面板打不开？

正常现象，面板随服务停止。重新点「启动服务」即可。

### Q4：改了面板端口打不开？

等待 5–10 秒，确认服务运行中，并检查 UCI 与 YAML 是否一致：

```sh
uci get adguardhome_lite.main.webport
grep -m1 '^  address:' /etc/AdGuardHome.yaml
```

### Q5：同时运行 OpenClash 时去广告不生效？

先确认 `agh_dns_redirect` 链存在：

```sh
nft list chain inet fw4 agh_dns_redirect
```

没有 `redirect to :53` 时，重新保存一次「接管 53 端口」。

### Q6：设备能连路由器但打不开网页？

多为设备没拿到 IPv4 DNS。补一条 DHCP 下发：

```sh
uci add_list dhcp.lan.dhcp_option='6,路由器IP'
uci commit dhcp
/etc/init.d/dnsmasq restart
```

设备断开重连后生效。

### Q7：重启后内核消失？

内核装在 `/tmp` 内存位置时会这样。重新安装内核，或把安装位置改到内置存储。

### Q8：忘记面板密码？

进入「基础设置 → 修改面板密码」，输入新密码保存即可，不需要旧密码。

### Q9：升级 OpenWrt 固件后？

`/etc/AdGuardHome.yaml` 和过滤缓存会保留；内核文件较大，不进入固件备份，升级后需要重新安装内核。

### Q10：开启「安全浏览」后解析变慢？

安全浏览依赖 `family.adguard-dns.com`，国内不可达时会拖慢解析。到 AdGuard Home 面板关闭「安全浏览」，或执行：

```sh
sed -i 's/^  safebrowsing_enabled: true/  safebrowsing_enabled: false/' /etc/AdGuardHome.yaml
/etc/init.d/adguardhome_lite restart
```

### Q11：过滤规则一直更新失败？

通常是直连 `raw.githubusercontent.com` 失败。插件会自动检测 OpenClash 的 HTTP 代理并写入 `http_proxy`：

```sh
grep -n '^http_proxy' /etc/AdGuardHome.yaml
```

为空时启动 OpenClash，再回插件重新保存一次设置。

## 7. 卸载与回滚

**LuCI 卸载**：系统 → 软件包 → 卸载 `luci-app-adguardhome-lite`。

**脚本卸载**：

```sh
sh install.sh --uninstall     # 恢复 DNS，保留配置与内核
sh install.sh --purge         # 同时删除配置、内核与统计
```

卸载会自动停止服务、恢复 DNSMasq、取消开机自启。

默认保留：

- `/etc/config/adguardhome_lite`
- `/etc/AdGuardHome.yaml`
- `/etc/AdGuardHome/`
- `/usr/bin/AdGuardHome/AdGuardHome`

彻底清理：

```sh
opkg remove luci-app-adguardhome-lite
rm -f /usr/bin/AdGuardHome/AdGuardHome
rm -rf /etc/AdGuardHome
rm -f /etc/AdGuardHome.yaml
```

回滚旧版：卸载本插件 → 安装 `luci-app-adguardhome` → 按旧版要求调整端口和工作目录。

## 10. 安全建议

- 不要将 `13800` 面板端口映射到公网。
- 默认密码仅供首次登录，请及时修改。
- 「接管 53」会调整 DNSMasq，若同时运行 Pi-hole、旧版 AdGuard Home 或自建 DNS，请先确认端口不冲突。
- 高级配置会直接修改 `/etc/AdGuardHome.yaml`，修改前请备份。
- 对安全要求高的环境，请为 LuCI 启用 HTTPS。
