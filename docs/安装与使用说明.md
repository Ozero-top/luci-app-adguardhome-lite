# AdGuard Home 一键版（luci-app-adguardhome-lite）

面向 OpenWrt / ImmortalWrt / iStoreOS 的 LuCI 插件。保持系统原有 LuCI 风格，用一个页面完成“装内核、接 DNS、看状态”，所有核心操作不超过 3 步。

> 本文档包含：安装包选择、LuCI 上传安装、安装验证、三步上手、功能说明、常见问题、卸载回滚与维护说明。

---

## 1. 设计原则

- **零基础可用**：安装后打开插件，按“安装内核 → 一键启用 → 打开控制台”三步完成，不需要命令行。
- **不破坏原有 DNS**：安装时不会自动修改 DNS；只有点击“一键启用”才会接管。停止服务、卸载插件时自动恢复 DNSMasq 原始设置。
- **官方内核**：运行时优先从 AdGuard 官方 CDN 下载最新稳定版内核；国内用户可启用 GitHub 反代优先下载，反代失败自动回退官方 CDN 和 GitHub 直连。
- **配置可控**：常用设置提供中文说明；高级功能可直接编辑官方 `AdGuardHome.yaml`，保存前自动校验并保留备份。
- **中文引导内置**：插件内“使用引导”标签包含 DNS 模式说明、常用功能入口和故障排查提示。
- **独立 UI**：保留主题左侧导航；右侧插件页面通过 iframe 完全隔离主题 CSS/JS，固定浅色草绿 / 米黄。

## 2. 安装包选择与兼容性

`dist/` 下提供两个安装包，**同一个路由器只能安装其中一个**：

| 安装包 | 适用固件 | 依赖 |
|---|---|---|
| `luci-app-adguardhome-lite_1.0.0-1_all.ipk` | OpenWrt 23.05 / 24.10、ImmortalWrt 24.10、iStoreOS 24.10 等使用新版 LuCI 的固件 | 自动安装 `luci-compat`、`curl`、`wget-ssl`、`ca-bundle` 等 |
| `dist/legacy/luci-app-adguardhome-lite_1.0.0-1-legacy_all.ipk` | OpenWrt 22.03 及更早的原生 Lua LuCI 固件 | 不依赖 `luci-compat` |

判断方法：

- LuCI 界面为较新的卡片式界面，且“系统 → 软件包”中能搜索到 `luci-compat`：使用 **modern** 包。
- 固件版本为 22.03 或更早，软件包列表中没有 `luci-compat`：使用 **legacy** 包。

> 插件与旧版 `luci-app-adguardhome` 存在冲突，安装前请先卸载旧插件。
>
> 已测试内核：AdGuard Home **v0.107.80**（2026-11-08 官方最新稳定版）。插件会在安装/更新时自动获取最新稳定版，无需随内核版本频繁更新插件。

## 3. 安装前检查

1. 路由器已联网，且系统时间基本准确（HTTPS 下载依赖证书校验）。
2. 路由器剩余空间建议不少于 **50MB**（内核解压后约 30-40MB，具体取决于架构）。
3. 如果已安装旧版 `luci-app-adguardhome`，先在“系统 → 软件包”中卸载：
   - `luci-app-adguardhome`
   - `luci-i18n-adguardhome-zh-cn`
4. 如果旧插件正在运行，卸载后确认 `/etc/init.d/AdGuardHome` 已停止；必要时重启一次路由器。

## 4. 通过 LuCI 上传安装（推荐，一键完成）

1. 打开 LuCI：`http://路由器IP`
2. 进入 **系统 → 软件包**（部分固件叫“软件包管理”）。
3. 找到 **上传安装包 / Upload package**。
4. 选择对应版本的 `.ipk` 文件并上传安装。
5. 等待依赖自动安装完成。首次安装需要联网下载依赖。
6. 安装完成后，在 **服务** 菜单下会出现 **AdGuard Home 一键版**。

> 如果已经安装过同版本的测试包，上传时若提示“已安装/无更新”，请先在软件包列表中卸载 `luci-app-adguardhome-lite`（配置、内核和数据会保留），再上传新包。
>
> 默认面板端口 `13800` 仅对**新安装**生效。已经安装过旧版的设备会保留原有 UCI 配置和端口；请在“基础设置”中把端口改为 `13800`，或删除 `/etc/config/adguardhome_lite` 后重新安装。
>
> 升级/重装时如果 UCI 中 `enabled=1`，安装脚本会自动重建开机自启链接并重启服务；面板通常会在约 10 秒内恢复。

如果上传界面提示依赖无法安装，请确认：
- 固件版本与安装包版本匹配（22.03 及更早请用 legacy 包）；
- 路由器可以访问 OpenWrt 软件源；
- 没有安装旧版 `luci-app-adguardhome`。

> 命令行安装仅作为备用方式（不是必需步骤）：
>
> ```sh
> opkg install /tmp/luci-app-adguardhome-lite_1.0.0-1_all.ipk
> ```
>
> 也可以使用离线自解压包（内含 modern 与 legacy 两个 ipk，自动选择）：
>
> ```sh
> sh /tmp/luci-app-adguardhome-lite_1.0.0-1.run
> ```

## 5. 安装验证清单

按顺序检查，全部通过即可正常使用：

### 5.1 菜单与页面

- [ ] “服务”菜单下出现 **AdGuard Home 一键版**
- [ ] 打开后“运行状态”卡片能正常显示
- [ ] 点击菜单后：左侧保留路由器主题导航，右侧显示独立插件页面（iframe 隔离，不加载主题 CSS），顶部 5 个标签均可切换

### 5.2 内核安装

- [ ] 概览页第 1 步显示“未安装”
- [ ] 点击“安装/更新内核”，进度框出现中文日志
- [ ] 完成后状态显示“内核版本 v0.107.xx”，按钮变为“重新安装/更新内核”

> 国内网络如果下载失败，先到“基础设置”选择 `GitHub 反代`（推荐 `gh-proxy.org`）后重试；日志会显示当前使用的下载地址和回退过程。

如果下载失败，日志会显示具体阶段；常见原因是路由器无法访问外网、DNS 解析失败或空间不足。

### 5.3 一键启用

- [ ] 概览页第 2 步“一键启用”可点击
- [ ] 点击后服务状态变为“运行中”
- [ ] “DNS 接管”显示“接管 53 端口”
- [ ] 页面显示面板地址、管理员 `admin` 和默认密码 `admin123`

### 5.4 面板与 DNS

- [ ] 点击“打开控制台”，能用默认密码登录 AdGuard Home
- [ ] 在 AdGuard Home“仪表盘”能看到查询统计
- [ ] 在局域网电脑上执行 `nslookup www.baidu.com 路由器IP` 能正常解析

### 5.5 可选：SSH 深度验证

```sh
# 插件 UCI 配置
uci show adguardhome_lite

# 服务状态
/etc/init.d/adguardhome_lite status

# 进程
pgrep -f AdGuardHome

# 上游模式：确认 DNSMasq 已转发到 AdGuard Home
uci get dhcp.@dnsmasq[0].noresolv        # 应为 1
uci get dhcp.@dnsmasq[0].server          # 应为 127.0.0.1#5333

# 运行日志
logread | grep -i adguard
```

> 接管 53 端口模式下，`dhcp.@dnsmasq[0].port` 应为 `1745`，AdGuard Home 配置中的 DNS 端口为 `53`。

## 6. 三步上手

### 第 1 步：安装内核

1. 打开 **服务 → AdGuard Home 一键版 → 概览**
2. 点击 **安装/更新内核**
3. 等待进度完成

插件会自动识别 CPU 架构（含 MIPS 大小端、ARM v5/v6/v7/v8、x86、RISC-V 等），从 AdGuard 官方 CDN 下载对应内核；失败会自动尝试 GitHub 直连。

国内网络如果访问 GitHub/官方 CDN 较慢，可先到 **基础设置** 把“GitHub 反代”设为 `gh-proxy.org` 等可用反代。启用后插件会优先通过反代下载 GitHub 内核，失败再回退官方 CDN 和 GitHub 直连。

### 第 2 步：一键启用

1. 点击 **一键启用**
2. 首次启用会从内置默认配置生成 `/etc/AdGuardHome.yaml`，并：
   - 使用默认账号 `admin` / 密码 `admin123`
   - 使用中文界面
   - 启用内置的 8 个过滤规则和 1 个白名单规则（含 AdGuard DNS、AdAway、AdRules、anti-AD、AWAvenue、GOODBYEADS 等）
   - 查询日志与统计数据保留 30 天
   - 采用“接管 53 端口”方式接管 DNS（DNSMasq 移到 1745）
   - 将上游 DNS 指向 DNSMasq（`127.0.0.1:1745`），避免与 AdGuard Home 自身的 53 端口形成回环

### 第 3 步：打开控制台

1. 点击 **打开控制台**
2. 使用概览页显示的地址、账号、默认密码登录
3. 登录后即可在 AdGuard Home 面板中：
   - 启用/添加 DNS 黑名单
   - 打开安全搜索、家长控制
   - 修改上游 DNS
   - 查看查询日志和拦截统计

> 默认密码显示在概览页“运行状态”卡片中，可点击“显示/复制”。如果忘记密码，到“基础设置”页底部“修改面板密码”重设即可。

## 7. 功能说明

### 7.1 独立管理页面

- **保留 LuCI 主题自带的左侧导航栏和顶部区域**，不替换、不隐藏路由器原有菜单。
- 右侧插件页面通过 **iframe 独立渲染**，iframe 内不加载任何 LuCI 主题 CSS/JS，因此布局、卡片、字体和配色不会被 iStoreOS、ZeroWrt、Bootstrap 等主题影响。
- iframe 高度会随内容自动撑开，**右侧页面内部不显示垂直滚动条**；上下滚动由外层 LuCI 主题页面负责。
- 右侧固定为**浅色草绿 / 米黄**配色（草绿主色 `#4f7d3a`，米黄背景 `#f3eddf`），不提供深色切换。
- 右侧顶部标签：**概览 / 基础设置 / 高级配置 / 运行日志 / 使用引导**。
- 页面通过 LuCI 会话鉴权，iframe 与 LuCI 同源，接口仍受 ACL 和 CSRF Token 保护。

### 7.2 概览

- **运行状态**：服务状态、内核版本、DNS 接管方式、更新通道、GitHub 反代、面板地址、管理员、面板密码、配置文件、工作目录
- **三步完成配置**：安装内核、一键启用、打开控制台
- **快捷操作**：启动、停止并关闭自启、重启、基础设置、高级配置、运行日志、使用引导
- **新手提示**：常见场景与故障入口

### 7.3 基础设置

| 设置项 | 说明 |
|---|---|
| 启用 AdGuard Home | 开启后启动服务；关闭后停止并恢复 DNSMasq 原始设置 |
| DNS 接管方式 | 默认“接管 53 端口”（与内置配置一致）；运行 OpenClash 且必须保留 DNS 劫持时选“OpenClash 串联”；也可选“DNSMasq 上游”或“仅面板模式”；切换时会自动调整插件内置上游，自定义上游保持不变 |
| 管理面板端口 | 默认 13800；不能使用 53、1745、5333 等 DNS 预留端口 |
| 内核安装位置 | 内置存储重启保留；内存临时适合小闪存，重启后需重新安装 |
| 数据工作目录 | 内置存储保留统计和过滤缓存；内存临时减少闪存写入，但重启后统计清空 |
| 内核更新通道 | 稳定版 / 测试版 |
| GitHub 反代 | `关闭（不使用）`、`gh-proxy.org`、`ghproxy.cc`、`ghproxy.com`、`ghfast.top`；仅加速内核下载，不改系统网络 |
| 当前状态 | 显示内核版本与运行状态 |
| 修改面板密码 | 浏览器本地计算 bcrypt 哈希，保存后自动重启服务 |

### 7.4 高级配置

- 直接编辑 `/etc/AdGuardHome.yaml`
- 保存前调用官方 `--check-config` 校验
- 校验失败不会覆盖原文件
- 每次保存保留 `.bak` 备份
- 保存后自动重启服务

> 过滤器、上游 DNS、家长控制等大部分功能建议直接在 AdGuard Home 面板中设置；高级配置主要用于排查问题和导入现成配置。

### 7.5 运行日志

- 系统日志中与 AdGuard 相关的最近 300 行
- 内核安装/更新日志
- 最近一次服务操作日志
- 支持手动刷新、每 5 秒自动刷新、下载为 txt

## 8. 四种 DNS 接管方式

| 方式 | 原理 | 适用场景 | 停止/卸载时 |
|---|---|---|---|
| **DNSMasq 上游（零冲突可选）** | AdGuard Home 监听 `5333`，DNSMasq 继续占用 `53` 并转发请求 | 不想替换系统 DNS 的家庭网络 | 自动恢复 DNSMasq |
| **接管 53 端口（默认）** | AdGuard Home 直接监听 `53`，DNSMasq 自动移到 `1745` | 与内置配置一致，客户端直接查询路由器 53 | 自动恢复 DNSMasq 端口 |
| **OpenClash 串联** | 保留 OpenClash 的 DNS 劫持；DNSMasq 收到查询后转发给 AdGuard Home（`5333`），AdGuard Home 再转发给 Clash DNS（`7874`） | 同时运行 OpenClash 且必须开启本地 DNS 劫持 | 移除转发规则，DNS 直连 Clash |
| **仅面板模式** | AdGuard Home 监听 `5333`，不修改 DNSMasq | 先体验面板，或准备手动配置其他接管方式 | 不修改系统 DNS |

切换方式时，插件会先恢复 DNSMasq 原始设置，再应用新模式，避免来回切换叠加配置。

> 以上方式只对“使用路由器作为 DNS”的设备生效。如果某台设备手动设置了 `8.8.8.8` 等外部 DNS，需要另行配置防火墙重定向才能强制接管；本插件默认不修改防火墙，以避免影响其他网络功能。

> **OpenClash 串联**会在 `/etc/dnsmasq.conf` 写入一段带标记的 `strict-order` + `server=/#/127.0.0.1#5333` 规则；停止插件或切换模式时会自动删除，不会破坏 OpenClash 的 fake-IP / TUN 代理。

### 8.1 停止或卸载后会怎样

- **只恢复你原来的设置**：插件在接管前会记下 DNSMasq 的端口、`noresolv`、`resolvfile` 和 `server`，停止/卸载时按原值写回。不会写入 `223.5.5.5` 等公共 DNS，也不会改动你自己的上游。
- **不会写死公共 DNS**：AdGuard Home 的上游只在插件自己写入过时才调整；需要外部上游时优先使用当前 Clash DNS，其次使用 WAN 下发的 DNS，只有在两者都拿不到时才回退公共 DNS。
- **OpenClash 仍运行时自动对齐**：如果 OpenClash 的 DNS 劫持规则还在，DNSMasq 会继续监听劫持的目标端口并指向 Clash DNS，避免“关掉插件后 OpenClash 和 DNSMasq 都上不了网”。
- **上游失效自动回退**：恢复后发现 DNSMasq 指向的本地端口已无进程监听（例如 Clash 已停止），会自动回退到 WAN DNS 并重启 DNSMasq。
- **解析自检**：恢复完成后会做一次解析测试；如果仍失败，会在运行日志中给出提示。

## 9. 常见问题

### 9.1 内核下载失败

- 确认路由器能访问外网，DNS 正常。
- 确认系统时间准确（HTTPS 证书校验依赖时间）。
- 国内网络可在“基础设置”中切换 `GitHub 反代`（例如 `gh-proxy.org`）；启用后优先通过反代下载，反代不可用再回退官方 CDN 和 GitHub 直连。
- 如果路由器使用 OpenClash / Clash 等 fake-IP DNS（域名解析到 `198.18.x.x`），插件会自动通过公共 DNS 获取真实 IP，并用 `curl --resolve` 下载，无需关闭代理或修改路由。
- 测试版只使用官方 beta 通道，不走 GitHub 反代，避免误装稳定版。
- 查看概览页进度日志或“运行日志”。
- 空间不足时，到基础设置把内核位置改为“内存临时”，或清理闪存。

### 9.2 启用后局域网不能上网

1. 打开概览页，点击 **停止并关闭自启**。
2. 插件会自动恢复 DNSMasq 原始设置；多数情况下立即恢复。
3. 如果同时运行 OpenClash，插件会让 DNSMasq 保持与 OpenClash 劫持端口一致，不会因为关闭插件而断开代理 DNS。
4. 如果仍不能上网，可通过 SSH 执行：

```sh
/etc/init.d/adguardhome_lite stop
/etc/init.d/dnsmasq restart
```

4. 查看“运行日志”，重点确认：
   - 内核是否存在
   - 配置是否被改坏
   - 53/5333 端口是否被其他程序占用

### 9.3 面板端口被占用

到“基础设置”把管理面板端口改为 `3001` 等，保存后使用新端口访问。

### 9.4 重启后内核消失

说明内核安装在 `/tmp/AdGuardHome/AdGuardHome`（内存临时位置）。重新到概览页点击“安装/更新内核”，或把安装位置改为内置存储。

### 9.5 忘记面板密码

到“基础设置”页底部“修改面板密码”，输入新密码并保存。无需知道旧密码。

### 9.6 升级 OpenWrt 固件后

- `/etc/AdGuardHome.yaml` 和过滤缓存会保留；
- 内核文件较大，不进入固件备份，升级后需重新点击“安装/更新内核”；
- 如果服务未自动启动，到基础设置重新保存一次或重新启用。

### 9.7 从旧版插件迁移

1. 卸载旧版 `luci-app-adguardhome` 和中文语言包。
2. 确认旧服务已停止。
3. 安装本插件。
4. 如果保留 `/etc/AdGuardHome.yaml`，本插件会直接使用它；第一次启用时会同步面板端口和 DNS 端口。
5. 旧版使用的工作目录可能不同，过滤器缓存/统计不会自动迁移，AdGuard Home 会重新下载过滤器。

### 9.8 与旧插件冲突

安装包内置 `Conflicts` 声明，检测到旧版 `luci-app-adguardhome` 时会拒绝安装。请先卸载旧版再安装。

### 9.9 如何确认当前架构

概览页的安装日志会显示识别结果，例如 `amd64`、`arm64`、`mipsle_softfloat`。如果提示架构不支持，请查看“运行日志”中的设备架构信息。

> 支持：x86_64/386、ARM64、ARM v5/v6/v7/v8(32位)、MIPS/MIPSel/MIPS64/MIPS64el、RISC-V 64、PPC64LE。暂不支持 LoongArch。

### 9.10 点击“停止并关闭自启”无效

- **停止服务后面板也会关闭**，这是正常行为；需要面板时请重新“启动服务”。
- 先确认插件本身完整安装：SSH 执行 `ls /etc/init.d/adguardhome_lite`。如果文件不存在，说明插件未安装或安装不完整，请重新上传 ipk。
- 正常停止会同时结束进程、恢复 DNSMasq 并删除开机自启链接；日志在“运行日志”或 `/var/run/adguardhome_lite_action.log`。
- 1.0.0-1 已增加残留进程强制清理：如果 procd 未成功结束进程，插件会自动 `kill` 并确保端口释放。
- 停止成功后页面会自动刷新显示“已停止”；如果页面仍显示运行中，手动刷新一次即可。
- 仍无法停止时，可 SSH 执行：

```sh
/etc/init.d/adguardhome_lite stop
killall -9 AdGuardHome 2>/dev/null
```

### 9.11 修改面板端口后 13800 打不开

- 修改端口后插件会停止并重启内核，请等待约 5-10 秒再访问。
- 只有服务处于“运行中”时面板才会监听；已停止状态下面板打不开是正常的。
- 升级/重装插件后如果服务未恢复，点击“启动服务”；新版本安装脚本会根据 UCI `enabled=1` 自动重建自启并重启。
- 确认 UCI 和配置一致：

```sh
uci get adguardhome_lite.main.webport          # 应为 13800
grep -m1 '^  address:' /etc/AdGuardHome.yaml   # 应为 0.0.0.0:13800
netstat -lnt | grep 13800
```

- 旧版安装会保留原来的 UCI 端口（可能是 3000），需要在“基础设置”改成 13800，或删除 `/etc/config/adguardhome_lite` 后重新安装。
- 如果端口仍被旧进程占用，插件的强制清理逻辑会处理；也可以执行 `/etc/init.d/adguardhome_lite restart` 后重试。

### 9.12 同时运行 OpenClash 时，去广告不生效

**现象**：AdGuard Home 状态正常、过滤器规则已加载，但查询统计里拦截数为 0，广告域名仍能正常解析。

**原因**：OpenClash 的“DNS 劫持”会用 nftables 把所有 53 端口请求重定向到它自己的 DNS，AdGuard Home 收不到客户端查询，自然无法过滤。

**处理（推荐，保留 OpenClash DNS 劫持）**：在插件 **基础设置 → DNS 接管方式** 中选择 **“OpenClash 串联”** 并保存。插件会自动：

- 让 AdGuard Home 监听 `5333`（避开 53 端口的劫持规则）
- 在 `/etc/dnsmasq.conf` 写入 `strict-order` + `server=/#/127.0.0.1#5333`，让 DNSMasq 优先把查询交给 AdGuard Home
- 把 AdGuard Home 上游设为 Clash DNS（默认 `127.0.0.1:7874`）
- DNSMasq 端口与 OpenClash 劫持目标保持一致

链路为：客户端 → 53 → OpenClash 劫持 → DNSMasq → AdGuard Home（过滤）→ Clash DNS（fake-IP）→ 客户端。停止插件或切换模式时，插件会自动删除转发规则，DNS 恢复为直连 Clash。

**可选方案（不推荐，会失去强制 DNS 接管）**：关闭 OpenClash 的 DNS 劫持，让 AdGuard Home 直接监听 53：

```sh
uci set openclash.config.enable_redirect_dns='0'
uci set openclash.config.redirect_dns='0'
uci commit openclash
/etc/init.d/openclash restart
```

**验证**：

```sh
nslookup pos.baidu.com 路由器IP    # 应返回 0.0.0.0
nslookup www.baidu.com 路由器IP    # 应正常解析
nslookup www.google.com 路由器IP   # 代理站点应返回 198.18.x.x fake-IP
tail -6 /etc/dnsmasq.conf                 # 应包含 BEGIN adguardhome-lite-openclash
```

> OpenClash 更新或重新执行“一键设置”后，如果 DNS 劫持被重新开启，插件会在下次启动时自动重新按“OpenClash 串联”方式对齐，无需手动处理。

### 9.13 关闭插件后发现 DNS 配置被改 / 无法解析

插件停止时只会写回接管前记录的原值，不会写入 `223.5.5.5`。如仍异常，按顺序检查：

```sh
# 1. 查看 DNSMasq 当前设置
uci show dhcp | grep -E 'port|server|noresolv|resolvfile'

# 2. 查看 OpenClash 是否仍在劫持 53
nft list chain inet fw4 dstnat | grep 'OpenClash DNS Hijack'

# 3. 测试解析
nslookup www.baidu.com 127.0.0.1
nslookup www.baidu.com 路由器IP
```

- 如果 OpenClash 仍在劫持，DNSMasq 应监听劫持的目标端口，并保持 `server=127.0.0.1#7874`；
- 如果 OpenClash 已停止，DNSMasq 不应再指向 `7874`，否则会解析失败，可在“基础设置”重新启用插件后再停止，让插件自动修正。

## 10. 安全建议

- AdGuard Home 面板默认对局域网开放，请勿把 13800 端口映射到公网。
- 默认密码为 `admin123`，建议首次登录后通过“基础设置 → 修改面板密码”更换。
- “接管 53 端口”会调整系统 DNSMasq，若路由器上还有 Pi-hole、AdGuard Home 旧实例、自建 DNS 等服务，请先确认端口不冲突。
- 高级配置会直接修改官方 YAML，建议修改前先复制备份。
- 通过 HTTP 访问 LuCI 时，管理员密码和面板密码均在局域网内传输；对安全要求高的环境请为 LuCI 启用 HTTPS。

## 11. 卸载与回滚

### 11.1 正常卸载

在 LuCI **系统 → 软件包** 中卸载 `luci-app-adguardhome-lite`。

卸载过程会自动：
- 停止服务
- 恢复 DNSMasq 原始设置
- 取消开机自启

默认保留：
- `/etc/config/adguardhome_lite`
- `/etc/AdGuardHome.yaml`
- `/etc/AdGuardHome/`（统计、查询日志、过滤器缓存）
- 内核文件 `/usr/bin/AdGuardHome/AdGuardHome`

这样重新安装时可以继续使用原配置和统计。

### 11.2 彻底清理（可选，SSH）

```sh
opkg remove luci-app-adguardhome-lite
rm -f /usr/bin/AdGuardHome/AdGuardHome
rm -rf /etc/AdGuardHome
rm -f /etc/AdGuardHome.yaml
```

> 该操作会删除配置、统计和过滤缓存，请先确认不再需要。

### 11.3 回滚到旧版插件

1. 卸载本插件（会自动恢复 DNS）。
2. 安装旧版 `luci-app-adguardhome`。
3. 旧版会读取 `/etc/AdGuardHome.yaml`；如端口/工作目录不同，请在旧版设置中调整。
