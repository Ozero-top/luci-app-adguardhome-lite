二、四种 DNS 接管方式，到底选哪个？

				

				
记住一句话：想看到每台设备、让所有域名都先过滤 → 「接管 53 端口」（装了 OpenClash、开着 DNS 劫持也照样能用）；不想让 AdGuard Home 占 53 端口 → 「OpenClash 前置」。剩下两种只在特殊情况用。

				

					

						
							
你的情况该选哪个为什么

						
						
							

								装了 OpenClash（DNS 劫持/转发开着），还想看到每台设备
								接管 53 端口
								插件会在 OpenClash 的劫持之前把设备的 53 查询收回 53，先交给 AdGuard Home 过滤，再经 DNSMasq（1745）→ Clash（7874）分流。
							

							

								没装 OpenClash
								接管 53 端口（默认）
								最直接：把 53 交给 AdGuard Home，所有设备默认都走它，过滤和统计都最完整。
							

							

								不想让 AdGuard Home 占 53，也不在乎逐设备统计
								OpenClash 前置
								Clash 先劫持，再把查询交给 AdGuard Home（5335）过滤；面板里来源全是 127.0.0.1，属于正常现象。
							

							

								没有程序抢 53，但想让 DNSMasq 继续当入口
								DNSMasq 上游
								DNSMasq 留在 53，收到查询后转给 AdGuard Home（5333）过滤。
							

							

								只想看看面板，或 DNS 已经由别的程序管了
								仅面板模式
								完全不动系统的 DNS，只开 13800 管理面板。
							

						
					

				

				
原来的「OpenClash 串联」已下线：DNSMasq 会优先用 OpenClash 写入的上游，查询被 Clash 抢先应答，AdGuard Home 实际收不到，旧配置会自动迁移到「接管 53 端口」。

			


			

				

					
三、每种方式的大白话说明

				

				
    
					
  • 接管 53 端口（默认）：相当于把「问路的前台」直接换成 AdGuard Home。设备一上来就问它，它先把广告域名拦掉，剩下的再转交给系统原来的 DNSMasq（被挪到 1745 端口）。
    
					什么时候用：想看到每台设备、让所有域名都先过滤；装了 OpenClash 也推荐这个。
    
					要注意：插件会自建一条 nft 规则，把设备的 53 查询在 OpenClash 劫持之前收回 53；如果这条规则没生效（面板会提示），查询仍可能被 Clash 抢走。
    • 
					
  • DNSMasq 上游：前台还是 DNSMasq，但它不再自己查，而是把所有查询转给 AdGuard Home（5333）过滤。
    
					什么时候用：你不想让 AdGuard Home 占用 53 端口，同时又没有程序抢 53。
    
					要注意：OpenClash 开着 DNS 劫持时不要用。
    • 
					
  • OpenClash 前置：设备先被 OpenClash 的劫持规则拉进 Clash 的 DNS（7874），Clash 再把域名丢给 AdGuard Home（5335）过滤，AdGuard Home 最后去问运营商/公共 DNS。
    
					什么时候用：不想让 AdGuard Home 占 53 端口，或者只关心过滤、不在乎每台设备各自的统计。
    
					要注意：Clash 内核必须运行；插件会自动把 Clash 的上游改成 127.0.0.1:5335，OpenClash 重启或「一键设置」后如果失效，回来重新保存一次即可。这个模式下面板里看到的来源都是 Clash（127.0.0.1），看不到每台设备的名字，属于正常现象。
    • 
					
  • 仅面板模式：什么 DNS 都不改，只把 13800 控制台开起来。
    
					什么时候用：只想先看看界面，或者你已经有别的 DNS 方案（比如另一台软路由）。
    • 
				

				
切换方式时，插件会先把 DNSMasq 恢复成你原来的设置，再按新方式配置，所以来回切换不会越配越乱。停止服务或卸载插件也会自动恢复。

五、常见问题

				

				
    
					
  • 面板打不开：确认服务处于“运行中”；停止服务时面板也会关闭。
    • 
					
  • 启用后不能上网：点击“停止并关闭自启”，插件会恢复 DNSMasq 原始设置。
    • 
					
  • 13800 打不开：等待 5-10 秒；确认 UCI 端口和配置一致；旧安装需手动改成 13800。
    • 
					
  • 忘记密码：基础设置页底部“修改面板密码”。
    • 
					
  • 升级固件后：配置会保留，内核需重新安装。
    • 
					
  • 「恶意/钓鱼」「成人内容」一直是 0：这两项分别依赖「安全浏览」和「家长控制」，插件默认不开启。安全浏览依赖境外在线服务，开启后如果解析明显变慢，请把它关掉。
    • 
					
  • 广告拦不住：先确认 DNS 接管方式对不对（推荐「接管 53 端口」，并确认面板没有提示劫持绕过）；能过滤的是广告域名，抖音、微信、爱奇艺这类“同一个 App 自己域名里的广告”DNS 拦不了，需要客户端级方案。
    • 
				

			


			

				

					
六、开机启动顺序（不用手动干预）

				

				
    
					
  • 顺序：DNSMasq（START=19）→ AdGuard Home（START=95）→ OpenClash（START=99）。
    • 
					
  • 为什么这样排：先让 DNSMasq 起来（接管 53 时它在 1745 提供本地解析），再让 AdGuard Home 占好 53/5335，最后才启动 OpenClash 去劫持 53 并把上游交给 AdGuard Home。这样开机过程中每个环节的端口都已就绪，不会出现「Clash 先起来、AdGuard Home 还没监听」导致解析失败。
    • 
					
  • 你不需要做什么：安装或启用插件时，`/etc/init.d/adguardhome_lite` 已注册为 START=95、STOP=01，开机自动按上述顺序执行。
    • 
				

			


			

				

					
七、安全提示

				

				
    
					
  • AdGuard Home 面板默认对局域网开放，请勿把 13800 映射到公网。
    • 
					
  • 默认密码 admin123，建议首次登录后修改。
    • 
					
  • 接管 53 端口会调整 DNSMasq，请确认没有其他 DNS 服务冲突。
